# V0.6.3.0 接口与架构

基础运行依赖为Python标准库。easy-tdx的MIT客户端源码随包隔离收录；取数时需要安装pandas/tzdata可选依赖。服务是本机HTTPServer，界面为单个HTML/CSS/JavaScript文件，状态保存在SQLite追加账本及来源捕获目录。

| 文件 | 职责 |
|---|---|
| common.py | 严格时间解析、规范JSON、哈希及错误 |
| data.py | CSV合同、快照导入、时间资格、缺失报告 |
| providers.py | TDX单股/全市场盘后包、InStock/Eastmoney只读单日、easy-tdx只读日线连接器；结构校验、截止日与来源口径 |
| market.py | 全市场盘后快照元数据内审；生成只读单日方向/覆盖观察，不生成候选或策略 |
| external.py | 外部分析原文存档、来源标签、日期/大小校验及内容哈希；不生成分析输入 |
| research.py | 描述协议、前缀事实、冻结卡、候选状态、风险及闸口 |
| store.py | 事务追加、UPDATE/DELETE阻断、哈希链 |
| portfolio.py | 订单计划约束；不做撮合 |
| reports.py | 事实复算、引用/时间审计、Markdown和全量ZIP导出 |
| bootstrap.py | 附件原始哈希校验及腾讯字段适配 |
| server.py / workbench.html | 本机API和网页交互 |
| __main__.py | 命令行 |

每份快照保存采集时间和实际导入时间；没有逐日来源首次可得时间的历史行保留null。研究卡冻结载入截至as_of的事实前缀，decision_at由程序实际生成。protocol_id、snapshot_id、全部事实/基准依赖ID与人工判断一起冻结。

行情行合同为`daily-bar-2`：`previous_close`是可选正数，只有来源实际提供时才留存。事实协议`descriptive-facts-2`在存在上一条输入行时使用该行close；只有当前快照单行且该行有`previous_close`时才回退使用它，并标注`previous_close_basis=row_previous_close`及缺失的`previous_bar_ohlc`。不推断前收日期，也不把前收值视为上一根完整行情证据。历史协议`descriptive-facts-1`的字段结构与计算保持不变，以便旧研究卡复算。

SQLite ledger是权威记录。CSV和Markdown是导出视图。快照同内容/元数据的重复导入复用首次记录；修订必须形成新快照/新卡。候选规则、边界和事件族固定，状态以candidate_event逐次追加。

候选状态视图和审计在读取账本时先按candidate_id分组事件，避免对每个候选重复扫描全量事件；复杂度由候选数×事件数降为候选数+事件数。账本仍是权威源，状态顺序仍按SQLite序号。

本版默认单进程使用：网页服务串行处理请求；不支持多个服务实例并发编辑同一个data目录。账本append使用BEGIN IMMEDIATE事务，但跨命令的候选语义校验没有并发数据库唯一索引，不能把它当成多用户服务器。

## 本机HTTP接口

GET不返回行情全量行，除明确导出全部记录的/api/export。POST要求`Content-Type: application/json`、JSON对象及有效`X-Workbench-Token`；缺少或媒体类型错误时返回415。界面从本机首页读取每次启动新生成的令牌。

| 方法 | 路径 | 内容 |
|---|---|---|
| GET | /api/state | 快照概况、全市场快照覆盖、协议、卡摘要、候选、候选登记尝试和闸口 |
| POST | /api/import | csv文本及metadata对象 |
| POST | /api/fetch/tdx | 用户明确的日期与1–5个普通A股代码；请求来源并分别保存行情快照/原始响应 |
| POST | /api/fetch/tdx-market | 用户明确的日期；导入沪深北盘后包中的有价普通A股并留存无价名单、来源覆盖计数与原始响应 |
| POST | /api/market-overview | snapshot_id；返回单日方向/交易所观察及自动候选、策略输出的阻断原因 |
| POST | /api/fetch/instock | 用户明确的日期和一个沪深普通A股代码；保存完整性未知的来源观察 |
| POST | /api/fetch/easy-tdx | 用户明确的截止日、一个普通A股代码和1–800根日线；当前日线标为不完整，保存服务器地址与解码行哈希 |
| POST | /api/external-note | 保存标记为未验证的外部输出原文；不写入行情表或事实证据 |
| POST | /api/analyze | snapshot_id/protocol_id/symbol/as_of/可选benchmark_symbol |
| POST | /api/card | 观察参数、人工必填字段、supports/opposes及可选修订 |
| POST | /api/candidate | card_id、场景、结构/事件族、结构起始日、边界、测试/响应/否定、期限 |
| POST | /api/transition | candidate_id/card_id/new_state/reason |
| POST | /api/risk | card_id/risk_type/reason |
| POST | /api/order-plan | card_id及订单计划约束；不执行交易 |
| POST | /api/protocol | 新描述协议；更换协议会保留旧版 |
| GET | /api/card?id=... | 单张冻结卡Markdown |
| GET | /api/external-note?id=... | 下载纯文本原文；固定附件名且不在页面解释执行 |
| GET | /api/audit | 本机审计JSON |
| GET | /api/report | 运行报告Markdown |
| GET | /api/export | 全量可读研究ZIP |

服务固定127.0.0.1绑定，Host白名单，跨站Origin拒绝，写入令牌校验，无跨域授权。此机制防止一般网页跨站调用，不是多用户认证。需要远程部署时应重新设计认证与存储；本版没有远程发布入口。

## 不在已实现范围

外部留档不等于安装或运行 PanWatch、TradingAgents、TickFlow、Global Stock Data 或 Finance Quant Skills。本版没有这些程序的服务端、数据库、模型调用、定时任务或交易API。

更多真实供应商行情抓取、授权验收、历史修订数据库、公告检索、行业/名单恢复、自动阶段标注、因果逐波端点、点数图、可执行W-BASE、事件成熟标签/结果库、可成交收益回测、试验预算/留出污染管理、Walk-Forward和六道统计验证。

行情连接器只在用户点击时联网。a-stock-data/InStock来源原响应另存于raw目录；easy-tdx高层API只提供解码行，本工作台保存其标准化行表示，不声称是TCP线缆原文。外部分析留档另以external_note账本类型写入原文，SHA-256审计与导出也适用。应用只认证本地文件与账本哈希一致，不认证外部报告或上游行情内容。准入边界见 `integrations/README.md` 和 `integrations/附件包审查_2026-10-09.md`。

任何拓展都需要独立规则/合同、预登记和测试。不能为填满结果表而生成统计数字。现有闸口有意保持BLOCK，没有可通过布尔开关直接晋级VALIDATION_ELIGIBLE的路径。
