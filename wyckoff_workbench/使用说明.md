# 威科夫中国市场研究工作台 V0.6.3.0 使用说明

V0.6.1 的历史修复与旧账本影响见 [V0.6.1 修复说明](修复说明_V0.6.1.md)；V0.6.2 的审查结论与性能优化见 [V0.6.2 审查与优化说明](优化说明_V0.6.2.md)；本版前收盘价字段与公式变更见 [V0.6.2.1 修复与验收说明](修复与验收_V0.6.2.1.md)。

版本日期：2026-10-09，Asia/Shanghai。当前软件属于描述性研究工具。全市场单日观察可用不等于自动选股、条件策略或投资方法有效。

## 1. 第一次启动

完整解压压缩包。Windows双击“启动工作台.bat”；macOS/Linux在解压目录执行 `sh start.sh`。需要Python 3.10+；基础运行无第三方Python依赖，不需要证券账号或数据账号。easy-tdx连接器为可选扩展，在项目目录执行 `pip install -e '.[easy-tdx]'` 后启用。

浏览器打开 `http://127.0.0.1:8765`。如果没有自动打开，手动输入地址。如果端口已被占用，在项目目录运行：

```bash
python -m wyckoff_cn serve --port 8766 --open-browser
```

如果Windows提示找不到py或python，先安装符合版本要求的Python，再重新启动。当前验收环境是Linux/Python 3.12，未在真实Windows桌面执行双击测试。

该界面只绑定本机回环地址。它不是云端页面；关闭启动窗口后页面服务停止。仅在“数据源接入”或“全市场观察”中点击获取时才联网读取行情，不连接券商。

首次导入附件快照时校验原始文件SHA-256。原始字段顺序按来源的date/open/close/high/low/volume转换到统一CSV，没有导入当前前复权作为历史PIT数据。个股、基准和市场指数各640根，共1920根，最后报价日期2026-10-08。每只标的单位保留source_native：附件对个股记为手，指数成交量口径未独立验收，不跨标的直接比较绝对量。

### 安装并使用 easy-tdx 行情扩展

在工作台目录运行：

```bash
pip install -e '.[easy-tdx]'
```

然后重启工作台。在“数据源接入”输入A股代码、观察截止日与请求根数（1–800），点击“获取并留档”。仅使用不复权日线；当天根会标记为不完整，应选择已结束交易日作为事实截止日。系统保存选择的TDX服务器和解码后日线行的哈希，不保存原始TCP报文。行情真实性、复权/公司行动、完整性和历史PIT未认证。


## 2. 今日的最低可执行流程

| 步骤 | 操作 | 输出与限制 |
|---|---|---|
| 1 | 运行概览检查最后数据日期 | 日期过旧时先导入新快照；不会把旧数据叫“最新行情” |
| 2 | 行情与事实选择证券、截止日、基准，点击复算 | 只显示截止前的事实；缺口保持unknown |
| 3 | 使用事实填写研究卡 | 主假设、竞争解释、证伪、待观察响应、独立风险和下一次观察都需填写 |
| 4 | 引用事实ID并冻结 | 冻结时刻使用服务器当前实际时间；保存事实前缀和协议版本 |
| 5 | 如确有研究理由，登记候选 | 人工边界及场景规则在登记时固定，不自动认为Spring或LPS已认证 |
| 6 | 后续获得数据、重新冻结新卡，追加状态 | 不复用旧卡补记当时未知响应；保留无测试、失效和过期路径 |
| 7 | 审计、导出、备份 | 全部记录都输出，失败与未知不删除 |
| 8 | 全市场观察页选日期、获取沪深北盘后包 | 留档单日有价/无价A股计数与原始包；可下载全部代码观察CSV；方向统计只作描述，不进行排名或推荐 |
| 9 | 归档外部AI/量化工具输出 | 只保存原文与哈希；不进入事实、候选或订单链路 |

单日全市场盘后包从“全市场观察”页获取。包内沪深北文件、证券代码前缀及来源最低行数阈值会被检查；所有原始字节按SHA-256留档。无正收盘价的证券显示为“无价、状态未知”，不能推断为停牌或退市。

本页单日上涨、下跌、平盘统计不等于威科夫吸筹/派发判断，也不是短中期标的排名。当前没有全市场历史OHLCV、点时股票池、有效复权/公司行动及已冻结策略规则，因此自动扫描与条件策略卡保持BLOCK。详细阶段见[全市场扫描与策略输出设计](docs/全市场威科夫扫描与策略输出设计_V0.6.3.md)。

## 3. 怎样导入自己的数据

### 使用已接入的数据源

在“数据源接入”页，填写日期和证券代码，再点击对应来源的获取按钮。单股TDX接口一次可选1–5只普通A股；InStock/Eastmoney每次一只、一天；easy-tdx每次单股、最多800根日线。全市场TDX盘后包在“全市场观察”页独立请求。网络访问不会在启动或分析时自动发生。

每次请求会分别保存标准化行情快照，以及原始提供方响应、响应SHA-256、来源URL和本机采集时刻。审计可验证这些原文件的本机哈希一致性；这不认证数据真实性、全市场完整性或历史可得时间。连接器数据只能按快照采集后进行描述，不能补签成历史回测或前瞻Shadow。

TDX连接器按来源字段声明使用成交量股数、成交额元，且只接受普通A股；InStock连接器把日线完整性和量额单位保留为unknown，因此该快照不满足冻结完整日频判断的条件。不同来源不会合并或自动挑选；请分别比较来源快照里的原始字段。

InStock 的选股、技术指标、筹码、策略回测和自动交易部分没有安装或运行。集成范围、来源许可证与边界见 `integrations/README.md`。

### 留档外部分析输出

用“外部分析留档”页上传或粘贴来自 PanWatch、TradingAgents-Astock、TickFlow、Global Stock Data、Finance Quant Skills 的 Markdown/TXT/JSON输出。系统原样存档（每份不超过1MiB），记录来源标签、用户填写的报告日期、引用、本机导入时间和SHA-256。原文可单独下载，完整备份也会包含原文。

此项不运行外部程序、不解析模型结论、不访问其数据库/账号、不把输出写入行情事实或证据ID，也不会自动建立候选。报告日期是用户提供的文字元数据，不是可信时间戳；AI建议、技术指标或回测绩效须由独立原始数据与研究流程核验。七个上传包的准入审查见 `integrations/附件包审查_2026-10-09.md`。

“导入数据”选择UTF-8 CSV，并填来源、价格口径、成交量/成交额单位及单位依据。空白模板在 `examples/行情导入模板.csv`。

| 字段 | 要求 | 未知/异常处理 |
|---|---|---|
| symbol | 字母数字及_.-，例如sh605366 | 保留前导零，不使用Excel的数字证券代码 |
| date | YYYY-MM-DD，同证券严格递增；本版支持1992年起 | 重复、乱序、未来行情拒绝导入；不静默排序或去重 |
| open/high/low/close | 正数且L≤min(O,C)≤max(O,C)≤H | 非法价格、NaN、Infinity拒绝 |
| volume | 非负，必填，单位在快照元数据声明 | 缺失拒绝，不补零；零值保留原值 |
| amount | 可空，来源真实成交额 | 空白保留null；不会用量×收盘价替代 |
| complete | true/false/unknown | 未声明完整的输入不能冻结日频卡；不会按日期自动猜完整 |
| status | normal/suspended/restricted/unknown | 缺失默认unknown；不从无报价猜停牌 |
| source_available_at | 有依据的带时区ISO 8601，可空 | 不从交易日期补15:00；填时间必须填依据 |
| availability_basis | 时间依据，未知为unknown | 依据不能替代缺失的来源时刻 |
| source_revision_id | 可选，源修订版本 | 空白为unknown |
| previous_close | 可选，来源提供的前收盘价；价格单位及复权口径须与本行OHLC一致 | 空白保留unknown；不从日期或其他来源猜测 |

网页导入使用本机当前采集/接收时间。旧日行情今天导入，只有当前快照描述资格。填写完整日线、PIT可比价或来源时刻属于用户声明，系统不会据此自动认证。

历史归档有独立采集依据时，可用CLI的JSON元数据提供captured_at；ingested_at仍由本机实际导入生成：

```bash
python -m wyckoff_cn import-csv --file 你的行情.csv --metadata 你的来源说明.json
```

元数据模板在 `examples/import_metadata_template.json`。真实数据使用manual_observation_snapshot；合成流程样本只能使用synthetic_demo。prospective_shadow不能通过导入参数开启。

每次新导入保留独立快照，旧快照与旧研究卡不覆写。本版不会自动合并不同快照的历史行：每个研究快照须包含所需窗口，基准与证券放在同一个CSV快照内，依日期匹配。

## 4. 数字究竟代表什么

全振幅=H-L，实体=abs(C-O)，上影线=H-max(O,C)，下影线=min(O,C)-L，收盘位置=(C-L)/(H-L)。零振幅时收盘位置为unknown。

`descriptive-facts-2` 按以下顺序取前收盘价：同一快照存在上一行时，使用上一行的close；当前行是单行输入时，才使用其可选`previous_close`。因此一行TDX日线包可以复算真实波幅=max(H-L,abs(H-Cprev),abs(L-Cprev))、跳空和净进展；但前收字段不提供上一根完整OHLCV证据，系统会列出`previous_bar_ohlc`缺口。多行序列的首行没有前收字段时仍为unknown。旧`descriptive-facts-1`卡不使用该回退，审计继续按旧公式复算。价格单位和复权口径需要一致；公司行动与交易日历未验收，相关结果仍不能当作合格历史策略特征。

相对量=当前量/前w根均量，排除当前根；默认w=20。预热不足或前序均量为零时为unknown。相对强弱=log(Ct/Ct-w)-log(It/It-w)，要求个股端点日期与基准端点日期相同，缺失不前向填充。基准与个股依赖ID均可追溯。

窗口按有报价根数计，不宣称已核验为完整交易日数量。默认值只属于固定事实描述协议，没有用这份已见样本择优。更换窗口必须新建协议，旧卡保持原协议；协议改变不是有效性升级。

截止日前缀筛选可用于练习，但附件样本已经看过，不能作为独立留出或未污染盲测。以后行情不能写入旧卡；后续结果也不能被补入旧时点事实。

## 5. 冻结研究卡与候选

每张卡至少引用一个可解析事实ID。支持/反对列表不得重复；同一事实有多种解释时写在竞争解释中，不计成多次独立确认。人工文本标human_unvalidated，程序不会用自然语言断定庄家、资金意图或未来涨跌。

冻结不允许自填旧decision_at。修订选择旧卡并填写原因，新卡通过supersedes_id链接旧卡；旧哈希及内容保留。账本通过SQLite触发器阻止普通UPDATE/DELETE，并用哈希链检查本机一致性。能整体重写数据库的人仍能重算全部哈希，本版不是第三方可信存证。

候选场景限W-LPS-BU和W-SPRING-TEST。登记时必须填稳定的structure_id、结构起始日、event_family_id、人工支撑/阻力、测试、响应、否定及等待到期日。结构身份由证券、冻结协议、结构起始日、支撑/阻力边界和场景生成；同一结构改名事件族或结构ID不能重复登记。到期日是描述性日历期限，不能冒充已验收的交易日计数。

允许路径包括：registered → context_established → awaiting_test → test_observed → response_observed；也可经过context_pending，并在合法前序状态进入invalidated或expired。需要测试的场景不能跳过test_observed。已响应记录不按等待响应期限自动过期，后续可追加失效观察。

每次转换使用候选登记后新冻结的卡，并要求行情在候选登记或上次决策之后才采集/导入，且具备新行情快照根、严格更新的报价日期及对最新本证券行情根的支持引用；协议/证券/模式也须一致。期限未到不记expired；到期后不能通过延长等待补记成功。文本条件是否真正成立仍由人工核对，程序校验引用、时序、路径和期限。

同证券、冻结协议、结构起始日、边界和场景的候选不能重复登记，失效后也不允许复制重试；被拒绝的重复登记尝试会追加在账本中。不同结构起始日或场景可分别登记，但不能据此宣称独立样本量。程序不提供按候选数量计算的胜率。

## 6. 风险与订单计划

网页风险观察单列保存，inventory_status为unknown，execution_status为not_simulated。它不会把“应退出”写成“已卖出”。公告原文、独立风险事实、公司行动及实盘库存仍需人工取得并审查。

CLI订单计划可使用 `examples/order_plan_template.json`，填入真实可核验卡ID及批次库存后执行：

```bash
python -m wyckoff_cn order-plan --request 你的订单计划.json
```

guard检查最早订单时间严格晚于决策、用户提供的申报单位、可用资金及费用、历史规则/日历/预算声明、T+1与可卖量减预留量。sellable_from必须由交易日历核实，不能用下一根有行情日期替代。新仓不能当日转可卖，超卖与现金不足会阻断。

REVIEWABLE仅表示提供的约束输入通过检查，不代表规则来源已经独立认证。每个计划为paper_plan_only，fill_status=unknown，filled_quantity和收益都为null。没有自动撮合、库存账本自动更新、盘口排队或订单执行接口。数量、预留和资金由用户提供并核验，跨计划自动占用管理尚未实现。

## 7. 审计、导出和迁移

网页“审计与导出”可执行本机审计并下载全部研究记录ZIP和Markdown报告。检查范围：原始CSV哈希、追加账本链、引用存在、冻结事实按原协议复算、研究卡及候选时间链。

导出包含ledger.json、每类记录CSV、每张冻结卡Markdown、标准化原始CSV、行情来源响应表示（easy-tdx为解码后标准化日线）、外部输出原文、审计结果、运行报告和逐文件SHA-256。CSV的payload_json保留完整字段；它是V0.5账本导出，不直接向V0.2空台账伪填数据。原始台账保留。

备份/恢复本机工作状态：先停止服务，再复制完整data文件夹到新机器的同名目录。ZIP没有自动恢复入口。默认数据目录可改：

```bash
python -m wyckoff_cn --data-dir /你的数据目录 serve --open-browser
```

API仅用于本机研究工作台；详细入口见docs/接口与架构.md。界面提交需要每次启动生成的会话令牌；服务拒绝非本机Host及跨站Origin。

## 8. 下一阶段的真实验收条件

| 阶段 | 要补齐什么 | 通过后的合法用途 |
|---|---|---|
| 数据合同 | 来源授权、字段单位、PIT修订、日历/状态/公司行动/历史股票池、完整性、公告时刻 | 对明确用途认证具体快照 |
| 最小定义冻结 | W-BASE、场景数值谓词、端点确认滞后、退出/期限、同族重叠及失败分母 | 可复现标签/候选，不等于有效策略 |
| 真实Shadow | 前瞻采集器、合格当日数据、先登记后观察、不可补签 | 独立积累未成熟/失败/未成交记录 |
| 现实成交 | 按历史规则的批次库存、申报、费用、延迟/限制/剩余暴露 | 仅在声明模型范围内研究模拟 |
| 统计验证 | 先预登记主指标/试验预算，成熟标签，清理重叠，Walk-Forward及留出，再做六道门 | 有效的成功/失败/证据不足结论 |

这些前置条件尚未完成。禁止把空结果写成0%胜率，把流程运行写成有效策略，把本机哈希验证写成数据真实或历史PIT认证。
