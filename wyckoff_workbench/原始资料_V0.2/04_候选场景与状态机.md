# 威科夫候选场景与观察状态

场景均从威科夫事件及供需响应定义，不用其它形态战法作入选条件。首版两个多头研究场景均在Shadow模式，尚未开始真实采集。

## W-LPS-BU：强势后的支撑测试

背景：已记录上涨延续或潜在吸筹/再吸筹，存在合法可知的强势表现与结构边界。SOS、边界突破和保持分别记录，不以单根涨停认证。

过程：强势后的Reaction → 对既有支撑/原阻力或区间内部的测试 → 已发生的向上响应。LPS候选与BU不是硬等号：LPS可在区间内部，BU关注突破后的回到原阻力附近。精确背景、参照选法和判断谓词必须在实验中冻结。

记录回撤幅度与用时、净下行推进、量、收盘、保持、同级前序波对比。缩量本身不是安全证明；若供应减少与买盘稀薄两种解释均成立则继续待定。

触发只使用事前登记的测试响应条件，例如当前完整收盘超过已冻结的测试响应参照；例子是定义方向，不是已验证规则。失效与等待期限先写，不因价格后来上涨补作成功测试。

## W-SPRING-TEST：下破失败后的检验

背景：下破前已登记支撑与结构位置。先记录下破，再记录收回，随后独立记录测试与响应；深度、收回时间、价格推进、量和后续保持都需可复算口径。

一根长下影不足以认证。首版研究的是“Spring候选及后续测试响应”子版本，不覆盖全部Spring传承；后续测试未出现的候选同样保留，不在最终出现响应后才补登记。

收回后再次失守、下跌扩展、反弹无推进或期限到达按既定条件失效/超时。确认发生在依赖数据可得时，不回填成下破日已知。

## W-WEAKNESS：派发/再派发风险观察

观察UT/UTAD、SOW、LPSY、原支撑变阻力、反弹收弱和向下保持。普通现货首版用于否决新增多头、检验已有持仓的退出需求及等待风险，**不产生无权限的做空策略**。

弱势观察记录风险请求时间、已有可卖库存、今日新仓、模拟退出订单、未成交和后续剩余暴露。风险信号出现不等于该价能卖出。UTAD不是必备条件，SOW也不能只靠一根阴线定义。

## 多头候选状态机

| 状态 | 进入依据 | 合法后继 |
|---|---|---|
| registered | 当时登记结构/场景/规则版本及观察原因 | context_pending / context_established / invalidated / expired |
| context_pending | 边界/事件/端点尚未合法确认 | context_established / invalidated / expired |
| context_established | 场景所需背景已知，竞争解释与否定已记录 | awaiting_test / test_observed / response_observed / invalidated / expired |
| awaiting_test | 预定测试尚未发生 | test_observed / invalidated / expired |
| test_observed | 已出现冻结定义的测试 | response_observed / invalidated / expired |
| response_observed | 事前响应条件在合法信息上成立 | invalidated；其余结果只追加outcomes |
| invalidated | 原候选否定条件触发 | 路径结束，独立结果观察可继续 |
| expired | 候选尚未响应且场景等待期限届满，包括未发生测试或测试后无响应 | 路径结束，保留未触发/错失记录 |

状态图是通用协议；W-LPS-BU与W-SPRING-TEST必须经过test_observed，不能借通用直接响应边绕过本场景测试。context_established直接到response_observed只供明确不要求回测的研究基线使用，并须独立定义。

response_observed仅表示当时响应成立；观察窗口内后续失效可转invalidated，原响应事件保留。窗口结束写outcomes，不把已响应者再按“等待响应期限”判expired。

data_blocked与structure_conflict是旁路字段，保留路径状态。恢复后按恢复时合法信息更新；一个日线中条件先后不明时记path_ambiguous，依预登记保守策略或上下界处理，不猜有利顺序。

弱势观察使用独立risk_state={observed, exit_requested, blocked, partially_reduced, reduced, unresolved, closed}；它描述风险处置，不冒充多头模式或成交状态。每次变化单列请求/决策时间与支持证据。

候选保留event_family_id，同股同结构的反复响应和两个场景重合按预登记策略归组，不能当独立样本重复计数。端点确认、范围/容差、窗口、触发、退出与试验预算仍须实验冻结，未填时仅做描述记录。

## V0.2响应档案

测试与响应使用15的独立response_id及response_status，与上述路径状态并存。test_observed并不表示测试成功，response_observed也不保证后续保持。窗口未满的not_yet_observed不能提前变成expired_without_response；资料缺失为unknown/data_blocked，不能伪装失效。

理论标签版本独立于候选路径。严格口径后期确认Spring不影响先前中性下破/收回记录；不同命名方式不新增一个独立事件族。初始吸筹与再吸筹九检按09选版本，不能因再吸筹缺卖出高潮就机械否决，也不能省掉本场景冻结的测试步骤。
