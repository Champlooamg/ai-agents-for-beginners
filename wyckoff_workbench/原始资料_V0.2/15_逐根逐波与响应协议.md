# 逐根、逐波与响应协议 · V0.2

依据五份笔记的量价阅读方法建立可复核表达，来源裁决见[14](14_五书学习与来源裁决.md)。这里定义事实字段与分析步骤，不声明预测价值；数值窗口、端点、阈值和响应仍须预登记。

## 一条分析链

背景与事前边界 → 当前价量事实 → 同级前序比较 → 主/竞争假设 → 预期响应与否定 → 新信息可得后记录响应 → 重新审视背景。先看市场/完整高周期定位，再读局部，最后检验局部解释是否与全局冲突。阶段是截至当时的摘要，不替代行为。

逐根字段、逐波字段和结构标签引用同一evidence_id。高量小推进即使分别支持停止、吸收、测试解释，也不能登记为三份独立支持。

## 逐根字段

使用同一公司行动口径的O/H/L/C与上一完整收盘Cprev，订单仍用原始价格。单根行情满足L≤min(O,C)≤max(O,C)≤H，量额非负；缺失不补零。

| 字段 | 定义 | 局限 |
|---|---|---|
| range | H−L | 不叫实体；H=L时位置/影线比例未知 |
| body | abs(C−O)，另存C−O | 小实体可能仍有大振幅 |
| true_range | max(H−L, abs(H−Cprev), abs(L−Cprev)) | Cprev未知则unknown；缺根或除权口径不一致先阻断 |
| close_location | (C−L)/(H−L) | 与02统一公式，只登记一次 |
| upper/lower_wick | H−max(O,C)；min(O,C)−L | 比例除以range；不能由长影线单独命名事件 |
| gap_open | O/Cprev−1 | 区分隔夜缺口、日内净推进与复权变化 |
| net_progress | C/Cprev−1 | 触及高点与收盘推进分开 |
| relative_volume | 当根量/事前w根均量 | w和缺根处理冻结；不能从缩量判断单一原因 |
| boundary_distance | C−冻结边界；标准化值另除事前冻结尺度 | 边界/尺度可得时间必须早于该事件；零尺度未知 |
| limit_state | 实际价格限制/停牌/成交受限事实 | 限价窄幅、封板缩量不当自然供需检验 |

高量/低量、宽幅/窄幅、高收/低收都是相对标签；保存参照值、窗口与版本，没有冻结口径时只写具体数值。“努力”可由活动量描述，“结果”由净推进、收盘、后续保持描述，不把量视作有符号资金流。

## 逐波字段与推力

冻结segmentation_version：端点算法、同价处理、确认滞后、重叠归属。每波同时保存start_event_at/end_event_at、confirmed_at、as_of和provisional。因右侧数据确认的旧端点不能倒签；未来Zigzag终稿不作过去已知波段。

每波记录方向、首末可比收盘与极值、净幅度、最高/最低伸展、交易间隔、有效报价根数、停牌间隔、累计量、每根平均量、累计成交额、前波回撤比例、价格区间重叠。冻结波段归属使同一根K线只在一波累计量中计一次；端点幅度与量窗口定义可以不同但须写明。部分波只与可比成熟度的记录比较。

累计量大可能来自波长更长，须并列日均量与净推进；不直接把不同长度累计量当力量强弱。速度采用log(Cend/Cstart)/交易间隔等预登记口径，间隔为零未知，不用绘图角度。拆股等使量单位不可比时记录转换依据或保持未知，不随意复权成交量。

“推力缩短”需选定同级已确认端点，分别比较相邻高点增量或低点增量、波幅、用时与量；逐根高低点和波段高低点是两个版本。缩短是趋势推进减弱的候选事实，也可能只是中继，不能固定次数后必然反向。价格活动量/推进效率可作探索字段，零推进与跨尺度问题单列，不由比值反推机构行为。

## 同一现象的竞争解释

| 现象 | 可以登记的解释 | 下一步可区分的事实 |
|---|---|---|
| 支撑附近高量、下行推进有限 | 卖出压力被买方承接；双向换手；限价约束 | 是否收回、再测试是否扩大弱势、向上响应是否实际发生 |
| 阻力附近高量、向上推进有限 | 买方压力遇到供应；双向换手；限价约束 | 能否保持上破或回到区间、回撤与随后推进 |
| 回撤低量窄幅 | 供应减少；需求不足/参与稀薄；停牌或限制影响 | 既有支撑是否保持，向上响应或弱势扩大 |
| 上行量减少 | 卖方供给减少；买方意愿衰减；比较窗口偏差 | 上行净推进、回吐、后续测试和同级波比较 |
| 停止量/高潮候选 | 原推进暂受阻；趋势继续前换手 | 后续反向响应、测试、边界与保持；不宣布最终顶底 |

使用“承接/吸收候选”时明确压力方向和可能承接方，不只写“买入性吸收”。没有方向识别数据时保持价格行为解释，不能升级为主动订单流事实。

## 测试与响应分开

测试档案必须包含：位置/背景、比较事件ID、价格与量的参照、test_predicate_version、测试事实、expected_response、response_window、invalidate_if、expiry。响应另记响应ID、event_at、最后依赖可得时间、confirmed_at、当时已发生的保持及response_status。

响应状态：not_yet_observed / observed / contradicted / expired_without_response / unknown。窗口未满时只能说截至as_of尚未观察到，不宣称以后不会跟进。依赖缺失写unknown并保留原路径；期限到达按冻结窗口处理，不能事后延长到成功。

边界中性事件先记support_breach、reclaim、test、up_response或resistance_break、failure_reentry、down_response；Spring/UTAD/SOS等另存label_definition_version与当时candidate/confirmed状态。B01与B04命名口径不同可以并存，不能用后期“严格命名”覆盖早期候选时间。

例如某低点在右侧第二根可得时才确认：低点event_at保留原日，confirmed_at写第二根可得时；只允许此时以后引用这个已确认端点。图形回标方便阅读不能改动归档决策。
