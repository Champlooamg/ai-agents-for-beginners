# 数据源验收清单

本清单判断一项具体来源能否支持某个研究用途。验收单位是“来源 × 端点/数据集 × 字段 × 市场/证券范围 × 用途”，不授予供应商整体可信标签。现有接口、外部项目和历史数据库均未因本文件而自动通过。

## 先登记来源契约

每个候选源建立唯一 `source_id` 和版本记录，至少说明以下内容。可复制[数据源验收记录](模板/数据源验收记录.md)：

| 项目 | 必须记录 |
|---|---|
| 来源身份 | 机构/供应商、端点、接口或文件版本、授权与再分发限制 |
| 数据范围 | 市场、证券类别、字段、频率、首末日期、更新时间、历史覆盖与已知排除项 |
| 字段口径 | 价格是原始价还是复权价；量、额、股本、币种、单位、时区、空值和舍入含义 |
| 时间口径 | 事件/交易发生时间、来源首次公开可得时间、系统实际接收时间、修订或回补时间 |
| 可复现性 | 查询条件、请求参数、原始响应位置、采集代码版本、快照时间与SHA-256 |
| 运行限制 | 限流、分页上限、延迟、历史保留期、故障状态、备用源及切换记录 |

端点返回当前值不等于提供历史时点值。对财报、公告、行业分类、指数成分、证券状态及规则，分别记录事实所属期与当时首次可得时间；日期相同不代表同一可得时刻。没有可复核依据的时点记 `unknown`。

## 逐类核验

| 数据族 | 最低验收内容 | 不合格时的限制 |
|---|---|---|
| 日线行情 | 原始OHLC、成交量/额、前收、交易日历、单位、复权因子及版本；停牌、缺根、涨跌停和零成交可区分 | 不能用于成交模拟或依赖其量价特征的历史验证 |
| 公司行动 | 分红、送转、配股、除权基准及公告/生效时间；复权前后能用原始数据复算 | 跨公司行动的结构边界和收益保持未知 |
| 证券状态与股票池 | 上市、退市、风险警示、停复牌、板块归属和权限状态的历史生效区间 | 不能宣称历史全市场覆盖；禁止用当前存续名单回填历史股票池 |
| 行业与基准 | 分类/成分及权重的历史版本、变更生效时间、基准行情的同口径价格 | 相对强弱只可描述个股与明确命名基准，不能作历史行业筛选 |
| 公告与风险 | 发布/披露时间、采集时间、公告版本、撤回/更正关系；原文可回查 | 不能将后续披露的信息放进先前决策，也不能把检索不到解释成没有风险 |
| 交易制度 | 交易所/板块/证券状态/生效区间/条款版本、暂缓条款与例外 | 受影响的日期和证券不得进入有效成交模拟 |

以上类别按研究用途取舍。比如仅做结构描述不需要完整公告财务字段，但若报告声称已排除公告风险，就必须对相应来源和覆盖作独立验收。

## 缺失与特殊状态

不得将以下情况合并：来源缺失、接口不可用、字段不适用、来源明确的零值、停牌/未上市/退市、无报价、涨跌停、以及“无法判断”。使用02规定的 `evidence_status`；已知停牌等状态另建可追溯事实。抽样发现差异时记录原值、来源、差异范围与影响字段，不以均值填补后继续验收。

## 验收步骤与结论

每一项验收需保留抽样方案、样本日期/证券、原始证据、对照依据、问题单和复核人。样本覆盖须在查看结果前确定，至少要有来源首末段、公司行动/缺失/停牌等相关边界案例；本体系不预设任意样本数量或容差，具体门槛须按用途预登记。

逐项检查：

- [ ] 字段、单位、时区、价格基准和证券范围有明确文档与实样核对。
- [ ] event_at、source_available_at、ingested_at及availability_basis能分开记录；历史时点依据可复查。
- [ ] 缺失、错误、停牌、零值和来源故障能区分；分页、限流和截断可发现。
- [ ] 更正、回补、复权和分类变更能追踪版本；冻结的旧快照可复现。
- [ ] 关键字段与独立权威材料或第二来源完成差异核对；差异有裁决记录。
- [ ] 授权、保留、使用和再分发边界已记录。
- [ ] 该来源与用途对应的阻断项、允许用途和复核日期已写入验收记录。

结论使用以下状态，不做加权总分：

| 状态 | 含义 |
|---|---|
| `not_run` | 尚未验收，不能引用为已核验来源 |
| `pass_current_only` | 可支持注明采集时点的当前观察，不支持历史点时回放 |
| `pass_prospective` | 可从实际留存日起做前瞻记录，不追溯授予过去的可得时间 |
| `pass_historical_pit` | 通过相应的历史版本、可得时间、覆盖和复算检查，可用于声明范围内的点时研究 |
| `partial` | 只通过明确列出的字段、时期或用途；未通过部分阻断相关结论 |
| `fail` | 发现无法接受的数据/授权问题；隔离该源并保存问题记录 |

某数据集的点时资格由其所有必要字段共同决定。一个源通过当前行情观察，不代表它能提供历史证券池、行业成员、公告时点、交易规则或真实成交数据。备用源切换后建立新的source_id/版本并重新核验，不默默拼接成连续数据。

## 当前适用状态

本版只有验收规则，尚无任何新增供应商、端点或快照获得 `pass_*` 结论。`a-stock-data`、Yuanastock、QVeris目录发现的底层provider、本地量化数据引擎、现有QDB及其它压缩包项目只能列为待审候选；技能说明或目录描述中的能力不替代实样验收。具体缺口见[建设状态](08_数据缺口与建设状态.md)。

## 当前数据源接入优先序（仅表示工作次序）

用户指定的顺序用于安排接入，不代表来源质量或策略有效性评级。**a-stock-data与Yuanastock均未通过数据验收；QVeris目录发现的底层provider也未通过。不得据此用于历史绩效验证或实盘信号。**

| 优先序 | source_id | 类型与拟用范围 | 当前状态与阻断项 |
|---:|---|---|---|
| 1 | `a-stock-data-v3.10.1` | 首要A股数据工具候选；优先核验日线OHLCV、公司行动/复权、交易日历和必要状态字段。每个接口实际调用的底层来源须单独登记 | 文档快照已固定到v3.10.1；来源、端点、字段、历史可得时间、授权及实样均`not_run`。不允许多源回退后不留痕 |
| 2 | `yuanastock` | 重要数据源候选；字段和用途待接口/账户文档确定 | 官网首页当前返回登录页；未取得公开API契约、数据条款或时点说明，验收`not_run`。凭据不存入研究库 |
| 工具 | `qveris-cli-0.11.3` / `@qverisai/mcp@0.14.5` | API目录发现/检查工具；本身不是行情来源 | Codex本地stdio MCP已配置；Windows凭据库保存凭据，启动器在子进程内读取；CLI仅通过一次性环境注入完成免费discover、inspect、schema probe。MCP启动及tools/list握手通过；未执行`call`，无credits扣除 |

一旦QVeris发现某个第三方能力，登记实际底层provider和tool_id为新的`source_id`，再按本清单逐项验收。a-stock-data版本升级、底层端点切换、Yuanastock文档/授权变化或QVeris provider变化都应追加新记录，不覆盖已冻结的来源契约。

### QVeris发现的A股行情候选

2026-10-08免费发现得到`cn_financial_pro.history_quotation.v1`（provider：`cn_financial_pro`，显示名：`cn financial pro 数据`）。这是待审API候选，不是已验收来源；QVeris的市场目录描述也不是数据使用授权或历史点时证明。

| 核验项 | 结果 | 对研究的限制 |
|---|---|---|
| schema | 必填字段为`codes`、`startdate`、`enddate`；schema probe返回`valid=true` | 只证明参数形状可通过目录校验，不证明响应完整或正确 |
| 调整口径 | 参数描述称`cps=1`不复权、`2/3`分红、`6/7`现金；默认值依资产类型而异 | 必须用原始响应与独立行情源复算，未确定具体返回字段的单位/复权质量 |
| 时效声明 | provider描述称沪深京日线在交易日18:30后尝试包含当日结算数据，否则回退最近结算日 | 仅为目录声明；交易日判定、实际返回日期与历史可得时间尚未核验 |
| 验证/权限 | `inspect`标记`verification_status=unverified`、`callable=false`，并将`execute`列为blocked；schema probe则返回`schema.valid=true`且`callable=true` | 元数据相互矛盾，执行状态未澄清前禁止取数 |
| 成本 | `expected_cost`显示`1 credits/result`；计费规则另称`0.00132 credits/quantity`、每次至少1 credit，价格确定性为estimated | 报价口径不一致，不可据目录估算批量成本 |
| 授权与PIT | provider身份之外的授权、商业使用、区域、历史覆盖/修订时点均unknown | 不能进入历史回测或收益结论；数据源验收保持`not_run` |

本次只做免费discover、inspect与schema probe，没有调用行情接口。即使schema probe显示可执行，仍不得越过上述冲突和验收闸口。
